# C17 精细建造能力评估与 Agent 建造方法

日期：2026-10-03（北京时间，采样跨 10 月 2 日午夜）。基线：CLI / DLL / skill 0.4.11，游戏 0.7.8.103 / XML 25。

本文是只读调研与方案，不代表下述拟议接口已经实现。本轮没有编辑飞机、修改插件代码、重新部署、启动 DSH 或操作未打开的飞机。

后续已据此细化 [0.5.0 落地计划](Implementation-Plan-0.5.0.md)和[验收方案](Acceptance-Plan-0.5.0.md)，包含代码位置、实施范围、效果目标与通过标准；仍为待实现方案。

## 1. 结论

当前工具能对机身、机翼及四类控制面进行细致的参数编辑，也具备位置、旋转、连接、输入绑定、对称、回滚等基础能力。它适合局部协助和受监督的迭代；**尚不能保证 Agent 独立、高效、稳定地完成当前 C17 这种程度的整机还原工程**。

主要障碍按优先级是：

1. **原生可调属性没有完整接入工具。** 窗体、贴花、文字、起落架、活塞等都有实际缺口；能读 XML、能查源码知识，并不等于可以写入。
2. **缺少统一的有效可写契约。** 游戏的 Overload 元数据、原生 UI 属性、序列化字段和工具实际允许操作的集合不同。
3. **缺少局部坐标、部件组约束与精确测量。** AI 经常必须手算世界坐标；现有包围盒/碰撞射线不足以评估复杂曲面、接缝及表面细节。
4. **缺少参考形状驱动的迭代闭环。** 有图可看，但尚无标定参考、截面误差、轮廓叠图、参数拟合、收敛与停止规则。
5. **可靠性和迭代代价仍需提升。** 本轮出现一次多视图相机恢复校验失败；多个编辑操作还可能反复重建整机。

这些大多可以沿用现有独立 DLL + 全局 CLI + skill 架构补齐。问题不在 CLI 接入形式，也没有证据表明需要先增加参数小数位数。游戏的原生几何表达能力仍构成上限：不能把有限截面、预设翼型或固定模型承诺为任意 CAD 曲面的精确表达。

`ValidateAttribute` 依赖 `GetOverloadMetadataLookup()`，只为 InputController、机身 offset/截面等补过明确扩展；`SelectPath` 只能选已有节点，不能通用地新增/删除动画关键帧或任意嵌套列表。原生 UI 中大量 `DesignerProperty*` 属性没有进入 Overload 元数据，正是缺口的主要来源。

不能把所有未声明的 XML 字段直接开放：其中也有派生值、缓存、自动依赖字段和结构引用。例如整流罩 radius 与发动机依赖应分别判定，不因存在于 XML 就认定它是独立自由参数。

## 3. 已有精细控制能做到哪里

| 能力 | 当前可用 | 尚缺少或需注意 |
| --- | --- | --- |
| 位姿 | 世界位置（米）、Euler 角、非均匀 scale；读取四元数 | 无统一的绕指定枢轴旋转、按零件局部轴位移、部件组刚性移动/约束求解。`part.add.rotation` 是模板增量；`part.update` 的 Part.rotation 是绝对姿态 |
| 机身 | 长宽高/offset、截面四角/四边、梯形、切割、空心、厚度、平滑、邻接同步/匹配 | 只补丁现有截面；没有任意增加截面的通用机身放样接口。`fuselage.match` 不负责摆位，也不保证数学上的切线/曲率连续 |
| 机翼 | 多截面替换、展向站位、弦长、偏移、原生翼型字符串、弯折、翼尖、采样；控制面范围与弦长比例 | 翼型必须被原生解析器支持；没有承诺任意翼型点列导入。截面 bend 不能直接当作局部扭转/安装角，原生 InputWingSlice 未提供独立 twist 字段 |
| 对称 | 原生对称组和受支持 shape 的镜像传播 | 原始 position/rotation/scale 的自动对称写入明确被拒，当前需分别计算目标姿态；镜像角点、翼型、输入反相不能统一逐字段复制 |
| 连接 | 挂点局部/世界信息、活动端/外壳、轴与原生兼容性检查 | 连接图不等于空间归属树；connect 不提供通用吸附摆位。不能强迫所有挂点重合，需允许作者故意偏置的装配 |
| 测量 | renderer/collider/editor AABB、碰撞射线、网格分析图、ID 拾取、原生截图 | AABB 不是轮廓，碰撞体不等于渲染曲面。缺少曲面最近点、截线、接缝距离/法线夹角、误差分布和机构扫掠净空 |
| 事务 | session/revision 防并发、临时 ID、检查点、undo/rollback | `batch.preview` 只检查请求结构；不是原生几何预演。检查点不跨游戏重启；回滚后需重读身份 |
| 三心 | 当前设计器的质量/升力/推力中心及贡献 | 不能用于证明静稳定、配平或飞行质量；外观验收与飞行验收应分开 |

Unity 变换使用浮点数，但本轮没有证据说明浮点精度是主要瓶颈。一个值能输入很多小数位不等于模型、碰撞或图像具备同等精度；分段/采样、几何生成器限制、参照误差和测量方式更重要。也不应仅提高所有采样数来解决精度，需按局部曲率和目标误差选取。

### 3.1 视觉与性能的实际边界

- `visual.capture` 已在内部读取真实 mesh 顶点/三角面，支持世界/零件坐标、多个组的联合视图与局部细节图。因此新增网格测量有基础；但当前公开输出主要是图像与空间清单，没有直接的曲面测量/截线 API。
- 分析图不还原原生涂装、贴花、透明裁切及 shader 变形；`complete` 也不能被解释为完整原生外观。原生截图需与分析图配合。
- 本轮四视图请求（front/right/top 正交 + isometric 透视，1280×800）返回 `camera_restore_failed`，没有保存这组视图。随后 current 单视图成功，`cameraRestored=true`，PNG 已打开。现象只出现于一次多视图调用，尚未证明根因是飞机规模或某一角度。
- 当前恢复校验用 `JToken.DeepEquals` 精确比较相机快照；响应未返回差异字段。需进一步区分实际恢复失败、浮点误差或相机矩阵更新，并保留诊断，不能简单删除校验。
- `part.update`、`shape.update` 等操作调用整机 `Replace`；一个含多个操作的 batch 可能重建多次。事务性不代表“一批只重建一次”。本轮未测 874 件飞机写入耗时，不能给出性能数字。
- 官方 C17 长度约 53 m。即便恰好充满 1280 像素宽的正交画面，也约为 4.1 cm/px；这只是说明性估算，不是本作品的测量值。整机截图不能检验毫米级接缝，必须局部取景并配几何量测。[美国空军资料](https://www.af.mil/About-Us/Fact-Sheets/Display/Article/1529726/c-17-globemaster-iii/c-17-globemaster-iii/)

## 4. 可交给 Agent 的建造方法

### 4.1 先明确参照与验收尺度

确定飞机型号/改型、目标状态（起落架/襟翼等）、全机比例、重点区域及允许误差。区分视觉近似、尺寸匹配、机构可动和飞行表现；用户说“像 C17”并不自动规定每一项都与实机相同。

优先采用有尺度的正交图、尺寸和截面资料；照片需记录视角、透视和可信度。单张照片不足以唯一确定三维形状。真实参考不足时，明确哪些细节是估计，不对这些区域报告虚假的毫米级准确度。

### 4.2 分层组织飞机和参数

建立“全机—机头/机身段/翼段/发动机吊舱/起落架—外形/机构/装饰”的设计清单，给每组一个角色和基准坐标。连接图是约束来源之一，不能直接 BFS 当作语义部件树。独立组必须保留共同坐标中的相对关系。

每组记录：当前 ID 与 session/revision、功能角色、基准件/轴、自由参数、冻结参数、对称策略、切割/贴花目标、输入绑定和验收目标。当前可在 Agent 工作区维护这份清单；稳定组句柄/原生设计意图存储尚未实现。

顺序建议：总体比例 → 主要截面与翼面 → 翼身/吊舱等过渡 → 机构与净空 → 玻璃/涂装/贴花/小件。不要在全机比例尚会变化时先精修数百个装饰件。

### 4.3 每个局部采用同一迭代流程

1. **观察**：获取当前身份，查询目标 `parts get` / `shape get` / `parts geometry`、挂点、对称与输入；只把与目标有关的数据交给模型。核查有效可写范围。
2. **定目标**：把“更像”具体化为哪条轮廓、哪个截面、相对哪个锚点、哪个间隙或颜色。固定前/侧/俯视的方向、比例、中心和状态，额外保留一张透视图检查观感。
3. **选少量参数**：只修改与当前误差相关的几项，例如先改截面宽高和偏移，再改圆角/曲率；不要同时改变外形、位姿和材质，导致无法判断改进来自哪里。
4. **准备一次受控修改**：建检查点，列出受影响组/邻接/对称/目标引用；同一个零件的相关修改尽量合入一个 operation。preview 只作为结构检查，不能当成几何验收。
5. **执行与复读**：用新 requestId 和预期 revision 执行，检查完整结果，再读实际生效参数、ID、形状、位姿、连接及必要的输入绑定。不能只看 success 或原始 XML。
6. **比较**：在相同相机与比例下看改前/改后图，检查其他视图、镜像侧与接缝；将新误差与最好版本比较。当前缺少自动指标的部分必须标注人工/视觉判断。
7. **保留或恢复**：达到目标则冻结区域；变差则 rollback 并缩小步长/减少自由参数。无改善、达到游戏限制或参考不足时停止，报告误差和原因；不无限循环重试。

当前工具可以支撑上述流程的基础版本，但缺口表中的字段无法靠此流程变得可写。后续应把测量、对齐、差异和部分参数搜索交给确定性工具，AI 负责选择目标、表达设计意图和判断未量化的观感。

### 4.4 示例：调整一段机头至参考轮廓

先固定相邻已验收机身，选中待调的前后截面及玻璃组，建立机体轴向站位。用侧视约束上下轮廓、俯视约束左右宽度、正视约束截面，再以局部透视检查圆角。

每轮只调该段 offset、两端宽高、必要的角半径/边曲率；保持连接、对称及切割目标。度量截面与接缝误差，超过容差才继续。若原生单段形状无法同时满足三个视图，增加适当的几何分段或明确近似边界，而不是无限改变 scale。**窗体切割、精确接缝测量和自动误差计算目前尚需新增接口**。

## 5. 建议如何补齐

以下接口名均为**拟议设计**，不属于当前 CLI 命令。

### 第一阶段：让可调属性真正可发现、可写、可验证

增加 `properties.describe/get/set`，合并四类信息：原生 UI 配置、Overload 元数据、原生序列化与有效值、工具特定适配器。每个属性返回类型、单位、坐标系、动态范围/枚举、当前有效值及来源、依赖、镜像语义、实际编辑入口，以及 `editable` / `readOnlyReason`。

优先接入：window/carver 的轮廓与目标；texture/text decal 的投影、图案/字体、尺寸、颜色、层级和目标；涂装/材质槽；起落架、轮子、活塞、整流罩；然后动画、仪表及其嵌套列表。复用已有复杂零件盘点，但逐字段区分 UI 可配置值、只读派生值及内部状态，不做任意私有字段写入。

可自动提取声明与范围；单位、坐标、互相约束、刷新动作和原生 setter 行为需适配器核实。目录未放置模板和 live part 应共享有效契约。用游戏自带纹理/字体/材质资源查询提供合法 ID，不允许 AI 猜资源名。

同时修复原生截图恢复诊断：输出恢复前后的差异及容差判定，对位置、四元数角距、投影分别比较，保留真正失败的错误；不要用“现在看起来正常”代替原始恢复证明。

验收：未放置模板能查到同一契约；代表字段合法输入写回一致、非法组合明确拒绝、默认值不误读、镜像正确、外观/拾取同步、撤销恢复。测试实际 C17 同类型的独立测试构型，不能靠修改这架只读参考作品来证明。

### 第二阶段：让 AI 能在局部坐标内操作并量化结果

增加 `transform.apply` 和具名部件组：支持世界/零件/机体/自定义坐标，指定枢轴平移旋转、组内相对位姿保持、参数联动与明确镜像。提供可选 `align`，区分挂点对齐、轴对齐、表面贴合、指定间隙；保持普通 connect 的拓扑语义，不能默认强制吸附。

增加 `geometry.measure/section/seam`：按选定的渲染网格或碰撞体计算最近点、截面轮廓、距离、法线夹角、指定区域偏差及对称误差。结果包含见证点、单位、坐标、identity、数据来源、采样/近似误差和是否完整。非闭合/透明/程序化 shader 网格无法可靠提供某项指标时返回 unavailable，不能把缺测填成 0。

内部已有实际 mesh 抽取，可在 DLL 主线程采样稳定状态后，把不可变网格交给独立计算。避免每次向语言模型发送整机全部三角面；返回局部统计、最差点与可视化，按需导出详细数据。

增加 `craft.diff`、变更影响预览及真正的隔离几何预演。原生状态变更后仍做全量必要校验；对同一 XML 状态上可合并的操作争取一次重建，依赖原生创建/挂接的操作按依赖拆段。不能为减少重建牺牲刷新、引用正确性和回滚。

验收：局部移动/旋转和组相对位姿有解析期望；曲面距离/截线以已知几何交叉验证；镜像、非均匀 scale、偏置连接、几何排除与未闭合网格均有用例。记录大型构型的实际耗时后再定性能门槛。

### 第三阶段：把参考形状变成可收敛目标

增加 `reference.register`、`fit.preview` 等能力，接收用户提供的参考图/尺寸/截面/网格（不涉及编辑未打开的游戏飞机），建立有单位的参照坐标、标定点、图像相机/正交比例、可见区域和不确定性。

`fit.preview` 针对少量开放参数，在范围、对称、接缝和冻结区域约束下做有预算的数值搜索。目标可组合轮廓距离、截面偏差、锚点偏差与接缝误差，权重按用户意图设置。参数不可辨识时提示增加视图/尺寸或减少自由度，而不是输出貌似唯一的答案。

输出候选参数补丁、改前/后残差（含最差位置）、叠图、预期影响、不能满足的目标和停止原因。预演与正式提交分开，最佳版本可恢复。AI 依据这些信息选择候选，不必每轮凭图片猜一组小数。

验收：先用已知原生参数生成参考，验证能恢复可辨识参数/几何且不修改冻结区域；再用有尺度的真实部件参考测评。分别验收几何、涂装、机构和建造效率，不使用单一“相似度百分比”概括全部质量。

## 6. 实施取舍

近期优先级是“有效可写属性 + 窗体/贴花/材质 + 截图稳定性”，随后是“局部坐标/组变换 + 几何测量”。前两阶段已能明显增强 AI 对高还原度工程的局部协助；参考拟合应建立在这些确定能力之上。

属性补齐可按族渐进交付，但动画、机构和目标关联不应简化成单字段放行。测量与变换为中等规模工程，参考标定/拟合和可靠预演是更大工程；本轮没有原型性能数据，不提供虚构的工期或还原度保证。

后续 skill 应描述上述局部迭代方法，并基于运行时能力发现选择流程。仅新增 skill 文本无法消除当前明确的可写缺口。本轮保留已有安装版本，未发布包含拟议接口的 skill。
