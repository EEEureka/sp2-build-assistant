## 目标与阶段

常规布局试验机，建议机长约 10–12 m、翼展约 12–14 m；选用适合工具测试的原生模板，不把初始尺寸当飞行性能保证。保留起始飞控芯片作为主控制，合理复用初始机身。每阶段独立控制写入范围并维护角色表。

## 每阶段闭环

1. 读当前身份、版本、台账及上阶段状态；写入前建检查点。阶段独占写入，协调端仅只读复核。
2. 查询 schema/目录再使用全局 sp2build；批次带当前 session/revision 和唯一 requestId；不直接修改存档、不绕过 CLI 调用 Unity、Python 源入口或任意注入。
3. 小批次建造、独立复读、geometry/raycast/shape/拓扑交叉验证；捕获图后必须真正读图，不把路径当视觉验收。
4. 按 AGENTS.md 更新唯一反馈台账：真实影响、查重、命令/输入/返回/版本/证据、准确状态。自己的脚本错误不作为产品缺陷；无发现时不凑反馈。
5. 输出阶段报告与机器可读状态，等待协调端核对。无缺陷或已确认不成立则协调端自动派发下一阶段，无需用户重复授权。
6. 有确认缺陷时，本阶段能独立完成的只读验收先收齐，暂停依赖失败结果的写入；协调端复现、改代码/文档、离线验证、部署，然后交 DSH 复验。只有验收通过才前进。
7. CLI/skill 修复可直接刷新后复验；DLL 修复时暂停 DSH，明确告知用户先保存当前阶段设计、重启游戏、重新打开同一飞机进入设计器。不得由协调端自行重启代替用户本轮流程。
8. 重启后先核对加载版本与当前飞机，重新获取身份、重建角色 ID 映射和检查点；原会话 checkpoint/referenceToken 不可复用。不自动从文件加载/替换飞机，不盲目使用旧 ID。

本次用户已经授权阶段建造与“发现反馈→核实→修订→复验”循环。遇到返回与实际不符仍需完整上报并停止依赖写入；协调端可在上述授权内调查与修复，不需要为常规重试另要一次许可。不可恢复状态、无法确认是不是同一目标飞机、或需要丢弃用户新增改动时才另外说明并询问。

## 验收边界

要求飞机包含所有约定组件、设计器数据与外观可复核、工具使用问题得到反馈和处置。设计器三心不等于静稳定性/配平/可飞性的证明。本次不进入飞行场景，也不宣称飞行性能已验证。历史 DSH 状态保留；最新直接验收以本文件和 docs/Agent-Feedback-0.4.9.md 为准。
