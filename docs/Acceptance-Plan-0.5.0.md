# SP2 Build Assistant 0.5.0 验收方案

设计日期：2026-10-03。2026-10-04状态：正在执行；本文件保留验收标准，通过与缺口另见[验收状态总览](Acceptance-Status-0.5.0.md)及[实施记录](Execution-0.5.0.md)。对应 [0.5.0 落地计划](Implementation-Plan-0.5.0.md)。

验收要证明的是：Agent 能发现可用能力，通过工具精细调整实际组件，观察真实效果，测出与目标的差距并反复改进，同时保持未涉及区域及恢复能力。HTTP/CLI 成功、XML 改值、schema 通过或截图文件存在都不能单独证明达到这一要求。

## 1 证据层级和验收环境

采用三条独立证据链：

1. **原生 UI 对照**：在相同基线分别通过游戏原生界面和 CLI 设置同一目标，比较原生有效值、几何/关联/材质及实际外观。不能只用新接口读回新接口写入的值。
2. **独立数值核验**：位姿与距离用手算可知的构型、独立双精度计算或已保存的原生网格求期望；复核脚本不得调用被测 DLL 的同一测量实现作为标准答案。
3. **完整建造任务**：Agent 接收目标和正式 skill，使用全局 CLI 完成三组局部任务。检查全过程及最终多视图，记录调用成本、失败和停止原因。

测试者可用源码定位故障，但正式任务的工具操作阶段不允许借助私有接口、直接改 XML 存档、修改 DLL、猜测未发布字段或读取隐藏目标参数。由当前 Agent 自验时如实标注“开发者自验”，不得冒充独立盲测；外部 agent 泛化能力需要以后单独测试，本轮不调用 DSH，也不自行新建其他 agent。

### 1.1 测试对象

| 对象 | 用途 | 约束 |
| --- | --- | --- |
| F0 当前 C17 原作 | 目录、有效值、只读截图、几何读取和大构型观察 | 不做写入试验；只读前后比对身份、飞机/选择/历史和场景实例 |
| F1 小型解析构型 | 正交/旋转方块、机身截面、已知间隙、镜像；用于数值与错误输入测试 | 新建并明确作为测试飞机的当前设计器会话；目标尺寸事先冻结 |
| F2 组件组合构型 | 窗体+机身、贴花+多目标、共享材质件、翼+控制面、发动机+罩、腿/轮/舱门/活塞 | 每项有原生 UI 制作的目标状态、基线和检查点 |
| F3 大型测试构型 | 874件量级的连续编辑、重建、失败恢复与性能 | 明确的可写测试副本或测试飞机，保持与 C17 相似的复杂族组合；仅达到相同件数不算同复杂度 |

工具始终只操作当前打开的飞机。未准备好 F3 时，大型写入质量/性能记为未验证，不能拿 F0 的只读查询冒充。创建/保存测试副本应走明确的准备流程，不能通过读取或修改未打开飞机存档绕过产品范围。

### 1.2 每轮开始和结束

记录 CLI/DLL/skill 版本、已加载 buildId、游戏/XML 版本、机器配置、当前会话、完整快照、场景实例、选择、相机、控制/动画状态、原生历史和基线图片。创建该会话的检查点；跨重启检查点失效，不能继续用旧 checkpointId。

每个用例保存原始命令、输入、stdout/错误、operationId、实际变化、版本和时间。结束时复读并独立比对期望范围：字段、位姿、连接、对称、目标引用、输入、变量、材料、几何与实例数。撤销历史按其语义检查；回滚允许留下合法历史记录，不能把“历史字节必须相同”用于所有恢复操作。

有玩家操作导致 revision 冲突时，该次测量作废并重建基线，不列为功能失败或通过。遇到飞机身份/恢复/场景不一致，停止后续写入；普通独立功能失败先留证，再继续无依赖测试，集中修订后复验失败项与受影响回归项。

## 2 精度和性能标准

以下是**本方案提出的发布验收值，不是现有版本测得的精度保证**。M0 将其写入冻结的验收清单，记录测试坐标范围、形状采样、模型大小和图像尺度。调整标准必须留下原因与影响，不得测试失败后无说明放宽。

| 指标 | 通过条件 | 限定和证明方法 |
| --- | --- | --- |
| 位姿数值 | F1/F2 位于基准附近100m范围内，位置误差≤0.1mm；旋转差≤0.01°；组内距离误差≤0.1mm | 以世界矩阵/四元数角距独立计算；不比 Euler 文本；不推广到任意远原点或动态飞行 |
| 标量/布尔/枚举 | 整数、布尔、资源ID、文本精确匹配；标量按字段单位/原生精度冻结容差 | 区分米、倍率、百分比、度；返回规范化值；不能用统一宽松容差掩盖错误 |
| 解析几何测量 | 已知间隙/截点/平面夹角误差≤0.1mm/0.01° | 对照解析解；曲面离散模型另报离散误差。最近距离不是穿透深度 |
| 局部外形目标 | E1 指定截线/接缝的已采样点最大偏差≤1mm；多视图轮廓 P95≤2px，最大≤4px | 相机固定、有效尺度≤1mm/px、明确ROI/可见范围；使用原生可表达目标，不称整机毫米级还原 |
| 已冻结区域 | 除明确列出的原生派生缓存等外，配置/连接/绑定/材质无变化；位姿按上述阈值 | 比对完整影响集外状态；排除规则提前列出，不能测试后扩大以抹掉差异 |
| 相机恢复 | 位姿≤0.1mm/0.001°；FOV/ortho/aspect相对或绝对误差≤1e-6；targetTexture/rect/模式等应恢复；投影控制点偏移≤0.1px | 同帧及至少后续2个稳定帧；矩阵系数辅助诊断，不能仅靠大矩阵的宽松相对误差判通过 |
| 视觉正确性 | 原生UI目标与CLI目标在固定环境下无缺玻璃/错目标/文字翻转/错材质/旧模型/错误遮挡 | 几何分析图+原生图+实际窗口；纹理/透明效果不得仅靠分析图验收 |
| 恢复质量 | 按既有规范化规则验证基线等价；若指纹不同则逐项解释；实际几何/外观/拾取/实例同步恢复 | 不把宽泛“语义相同”用于掩盖额外修改；revision可以推进但需返回正确身份 |

性能在同机、同设置、稳定帧下采集，冷启动单列。建议发布门槛：F3 局部≤8件的属性/测量查询 p95≤2秒；纯属性/位姿8件批次 p95≤5秒；4张1280×800原生图 p95≤10秒。每类至少30次，报告全部样本、p50/p95/max及游戏主线程停顿。F3 若未经实测，不填推算值。

性能对照选择 0.4.11 也能做的相同任务：在保持结果正确的前提下，串行纯编辑的重建次数应从多次减少为每个可合并段1次，耗时中位数目标降低≥30%。新增能力旧版无法完成时记录“不支持”，不能用其无限/零耗时制造提升比例。图像任务和复杂原生创建单列，不能混入平均值稀释慢操作。

## 3 功能测试矩阵

### T01 原生截图和相机恢复

**步骤**：在 F1 和 F0/F3 分别设置普通及非整数姿态、滚转、不同焦距/正交大小；复现历史 front/right/top 正交+isometric透视四视图请求；再测试 current、每个预设和自定义方向、不同画幅/焦点。每套多视图连续10轮，跨至少2个游戏会话。

**通过**：所请求的每张图均下载、实际打开；视角/投影/构图符合输入。相机状态及后续帧通过第2节标准；无累计漂移，选择/飞机/历史不变；原生窗口没有第二架飞机。失败不能只返回笼统错误，必须给差异和恢复状态。

**独立证据**：原生窗口截图、恢复前后控制点投影、camera diff、完整manifest；不把 `cameraRestored=true` 自我声明作为唯一证据。

### T02 截图异常路径

**步骤**：离线注入渲染/编码异常、第二张图失败及中途取消；实机执行可控的错误输入、预算超限、过期revision、排队取消、正在渲染后的取消。不同取消阶段分别记录实际进入的分支。

**通过**：异常后相机/RenderTexture/灯光/输入控制仍恢复；能继续拍下一张。相机真实偏离时必须失败并输出字段差异；禁止仅放宽容差让测试变绿。取消已完成任务只验证已完成分支，不能冒充中途取消覆盖。

### T03 全目录发现和真实可写契约

**步骤**：分页枚举运行时全部类别/模板，包含当前飞机未使用的类型和组合模板；对照原生UI声明、已知序列化字段与注册清单。核查窗口、贴花、文字、罩长度、materials等已知反例。

**通过**：所有模板均有能力结果或明确错误；所有纳入审计全集的属性均有来源和editability，未知不伪装成只读/默认0。动态依赖有原因，目录读取不生成场景件。范围内全部必需字段可写且有测试ID；其余未支持清楚列出。不存在“宣称editable但因未实现直接unsupported”的条目。

**证据**：`coverage.json`列分母定义、发现数、已支持/条件/未支持/未知数、排除项和逐字段测试；分母不能只取当前注册成功的属性。目录模板重复属性和单一类型字段分别统计，不能用模板数量冒充属性覆盖率。

### T04 有效值与原生界面对照

**步骤**：在 F2 基线用原生UI设置目标，记录实际值/图/几何；恢复基线，再由CLI设置相同目标。覆盖每个必需适配器的默认、省略值、常用值、边界，以及同名modifier多个实例。

**通过**：数值、原生状态及效果与UI目标一致；无需打开属性面板才能生效；切换选择后面板显示正确。合法规范化有requested/effective/原因，原生派生值能读清。镜像值按原生语义处理，不能只是复制。

### T05 非法值和动态资源

**步骤**：逐字段自动生成错类型、NaN/Infinity、越界、非法枚举/字体/图案/材质槽、非法目标ID；测试值单独合法而组合非法、宿主不存在、样式切换后旧选项失效、条件字段缺上下文。资源分页需覆盖末页。

**通过**：明确错误码、字段和约束原因；无静默默认回退或裁剪。前置拒绝不改飞机；原生阶段失败恢复完整状态。默认值、安全值和边界成功不能代替非法输入用例。

### T06 窗体和切割目标

**步骤**：在有内外两层壳体的机身上添加窗口；调整上下宽/偏移、圆角、高度、深度、penetration、hideGlass/透明；只针对指定壳体切割；测试目标增删、镜像和宿主移动。

**通过**：目标壳体形成期望轮廓，非目标壳体不受影响；玻璃显隐/透明正确。改大后新增区域的点击/射线/几何符合原生UI对照，旧区域没有无依据残留。若原生游戏本身的渲染切割与碰撞语义不同，分别报告，并以原生同操作结果为准，不能强求两者完全重合或宣称物理开洞。

### T07 贴花和文字

**步骤**：在曲面和相邻件上设置不同投影/深度/倾角、尺寸、tiling、透明和优先级；修改文字/字体/字号/对齐；测试中文/特殊字符可支持性和镜像；移动宿主及投影器，检查只作用指定目标。

**通过**：原生图显示文本和图案内容、方向、尺寸及遮挡正确；未列目标没有串色/穿透贴到背面。Part与投影器两套位姿被正确解释。字体不含字形时明确限制，不能以字符串已存储冒充字形显示正常。

### T08 材质作用范围

**步骤**：让3件共享一个材质；只改其中一件时克隆材质并赋指定槽；另测显式共享编辑、玻璃/预留槽、容量不足、无效资源及撤销。

**通过**：局部模式只有目标槽变化，另2件材质和外观不变；共享模式返回全部影响件。颜色/金属度/光滑度等与原生UI目标一致，渲染效果实际打开核验。当前飞机Theme变化可撤销，全局主题及其他飞机资源不被修改；此项用全局对象/持久配置前后审计，不读取其他飞机内容。

### T09 整流罩和旋转伸缩机构

**步骤**：修改罩长宽高/样式并保持发动机依赖；配置活塞行程/速度/方向和铰链角度/速度，检查输入与活动端。以原生可用的设计器预览检查端点姿态；无法预览的动态效果标未验证。

**通过**：实际几何、挂点和拾取刷新；配置UI值正确；活动端/外壳角色不混淆；输入映射保留。不能用“改了速度字段”证明飞行中运动速度已验证。本版承诺的是配置与设计器效果，飞行行为单列。

### T10 起落架轮组和舱门

**步骤**：改腿/轮尺寸、支杆/扭力臂、偏置、悬挂、转向/制动及舱门轮廓/厚度/铰链；先设自动铰链，再设手动两轴；保持原有动画关键帧、父链接及控制输入。使用原生预览检查能到达的收起/放下状态。

**通过**：与原生UI目标一致、无错误悬空轮组或双重移动；保留字段完整。未知宿主或无效组合拒绝。离散状态净空不代表连续扫掠无碰撞；完整动画编辑不在本版，不因此宣称验收覆盖。

### T11 局部坐标和枢轴变换

**步骤**：F1 使用有平移/旋转且非零枢轴的基准件，分别按世界、零件、机体、自定义frame操作；比较绝对与增量模式；包括四元数q/-q、跨±180°、非法零四元数和非均匀scale的被选零件。

**通过**：独立矩阵计算与实际位姿符合容差；相同请求重试只执行一次。刚性变换保留既有单件scale，不能产生错误剪切；本版未支持的组缩放明确拒绝。语义不借用part.add的模板旋转增量规则。

### T12 组和对称随动

**步骤**：选择机翼+控制面、发动机+罩、带窗体/贴花目标的显式组，绕外部枢轴旋转；测试两侧同时入组、只改一侧、native autoResize、组外连接、漏选随动件、旧revision/ID复用和玩家改动。

**通过**：每个实际受影响件只变换一次，组内相对位姿保留；影响集外保持；镜像结果正确。遗漏依赖返回可解释冲突或经显式策略扩展的清单，不能暗中遍历整架飞机。旧组句柄不得静默指向复用ID。

### T13 距离法线和真实网格来源

**步骤**：F1 设置12mm解析间隙、倾斜平面、嵌入/相交以及仅AABB相交而真实表面分离的构型；对renderMesh/collider分别查询；补非均匀缩放、隐藏/无网格件与被裁切表面。

**通过**：解析距离和法线符合容差；返回双方见证点及完整性。数值独立核算一致；碰撞与渲染来源不能混用。相交的无符号距离为0时不能报告穿透深度0；无法测量必须unavailable。

### T14 截线和接缝

**步骤**：平面切已知盒/棱柱，再切圆角机身与翼根；指定一段接缝，故意在中段制造突变或小缝，测试稀疏/密集采样、开放边界和法线翻转。

**通过**：解析截线正确；接缝统计带有效样本、位置和采样密度，能够指出被植入的缺陷。独立网格截交/距离核算一致。若采样不能界定连续最大误差，输出明确限于采样点，不给无依据的全段“通过”。

### T15 预检查差异和影响范围

**步骤**：预检查单字段、跨字段、材质共享、对称、宿主/目标变化；查看检查点与当前的差异；故意让只看结构合法的请求在原生阶段失败。

**通过**：preview清楚区分已检查和待原生验证；不改变场景/历史。diff列出全部实际变化、发生原因与意外影响，能显示1mm/小角度变化；不会把基线缓存全部判为用户修改，也不能吞掉真实小改动。

### T16 事务恢复和场景生命周期

**步骤**：分别在第1步、中途和提交/刷新阶段注入失败；多次重建后CLI undo、原生Undo按钮、checkpoint rollback；删除后同批新增触发ID复用；中途取消/超时查状态。中途故障注入仅用于测试构建，记录运行分支。

**通过**：未完成批次恢复到合法基线，ID/目标/对称/输入/材质/变量/选择均正确；恢复后新的鼠标命中与真实窗口一致。设计器容器总/活动实例各1，无第二架飞机；下一次正常编辑能成功。若恢复失败则明确stateUncertain并阻止新写入。最终发行DLL另做无注入回归。

### T17 合并重建正确性

**步骤**：比较相同操作列表的保守逐项执行与EditPlan合并执行；包含同字段多次写入、先样式后尺寸、临时ID引用、原生连接autoResize、删除和创建边界。

**通过**：最终有效状态、几何、挂点、影响集和恢复语义一致；可合并纯数据段rebuildCount=1；依赖原生状态的边界次数如实报告。不能以少一次重建换取漏掉回调、错误执行顺序或旧碰撞体。

### T18 大型构型和性能

**步骤**：F3至少30轮“局部查询→8件小改→多视图/测量→回滚”，采集第2节指标；覆盖一个含窗口/贴花/镜像和非平凡连接的区域；跟踪内存/实例/缓存是否持续增长。

**通过**：无累计偏差、内存/对象持续泄漏、历史损坏或错误引用；满足冻结性能门槛。报告查询/计算/渲染/重建各阶段，超时要查最终状态，不当成失败恢复已经完成。

### T19 CLI 安装契约和兼容

**步骤**：从正常工作目录运行全局sp2build；检查help、commands list/schema、CLI/operation映射、同步/异步/--output结果；将返回按已发布schema校验；新CLI配旧DLL执行新增命令。

**通过**：无py -3入口指导；错误码和输出结构完整；新旧功能判定基于已加载DLL能力，旧DLL明确unsupported_bridge_feature；旧调用保留兼容。部署哈希一致不代替loaded buildId确认；skill包内所有链接与命令均有效。

### T20 skill 和可理解性

**步骤**：按发布skill从目标开始，查询能力、选族、准备补丁、检查结果、看图、测误差、回滚再试；特意加入一个本版未支持的Animator或仪表目标。

**通过**：Agent能用文档和schema完成支持任务，遇到未支持任务准确说明边界，不猜字段、不用scale硬凑、不直改存档。记录额外查询、试错和信息不足；未知/条件能力不会被错误解释为成功或游戏不支持。

## 4 三组效果验收

这些任务用来验证实际建造能力。每组先由原生UI制作一个目标基线，固定三视图、必要尺寸/截面和容差；Agent只取得目标说明、图片/可用尺寸以及有意扰动的起点，不取得隐藏目标XML或完整目标参数。目标必须在本版原生形状和必需字段内可表达，另加一个不可满足目标验证停止行为。

原生UI标准答案和AI结果由复核脚本比较；复核脚本可读取工具导出的当前网格与状态，但不得回调被测测量实现充当独立答案。主观观感由用户最终评价；用户尚未评价时标注待评，不能用AI自评“还原度100%”替代。

### E1 机头截面和驾驶舱玻璃

**目标**：一个约2m长的局部机头，由多段机身和至少4个梯形窗体组成。给前/侧/俯视目标、若干截面/锚点及玻璃边界；扰动宽高/偏移/圆角、窗口位置或轮廓。固定后方已验收机身。

**要求Agent完成**：找出相关件及可写字段，按截面→接缝→玻璃的顺序微调，至少记录两次真正的“测量后决定下一次修改”，保留最佳结果；不手动重写整架飞机。

**通过标准**：第2节的局部外形/轮廓容差；窗体只作用指定壳体；无目标外改动、镜像错位、旧拾取区域。最多12轮候选修改，最多30次写入批次（查询不限但记录总数）；超出或未达标记未通过，不删除失败过程后重新统计。3个预先固定的扰动起点均须通过。

**证明范围**：能协助机头/玻璃的参数化精修，不证明能仅凭一张C17照片得到真实机头。

### E2 吊舱装配和表面细节

**目标**：一组发动机/罩/挂架与另一独立翼段共同展示，保持相对坐标。设置罩长度目标、以局部轴5mm平移/绕指定枢轴0.2°旋转、规定挂架间隙；增加一条有明确宽度的贴花和一段文字。故意保留非零挂点偏置作为合法装配。

**通过标准**：实际位姿符合0.1mm/0.01°数值标准；组内相对关系保持，指定接缝/间隙≤1mm误差；connect不擅自吸附；罩/文字/图案真实显示，镜像和材料范围正确。联合视图证明两组相对位置，局部视图证明细节；不能各自居中后只比较外观。最多8轮候选修改、20个写入批次，3个固定扰动起点通过。

**证明范围**：能精确定位和装饰组件簇，不能代替真实推力/重量分布与飞行性能验证。

### E3 起落架和机械附件

**目标**：给腿/轮/舱门/活塞组合的尺寸、轮心锚点、铰链轴和行程目标，保留已有动画/输入。要求修改外形与位置，检查可用的原生收起/放下预览，再故意撤销一版效果较差的调整。

**通过标准**：关键尺寸/位姿按数值容差匹配，轴和活动端正确，原生预览中的两个离散状态无新增可见错误；配置值与UI目标相同。动画关键帧/父链接/输入完整保留，撤销恢复后继续编辑成功；镜像侧同步符合原生规则。最多8轮候选修改、20个写入批次，3个固定扰动起点通过。

**证明范围**：能精修本版支持的机械配置和静态/离散姿态，不证明完整收放过程无碰撞，也不证明飞行中的动态表现。

### 4.1 衡量易用性

每组保存总调用数、读/写/失败/回滚次数、耗时、模型实际看过的图、额外手算/脚本步骤、未找到参数的次数、最终误差和停止原因。正常任务不应出现因字段名/单位/CLI与operation混淆而失败的调用；此类问题修正文档/契约后重跑受影响任务。

不得只统计成功调用或只展示最终漂亮截图。3个固定起点检验可重复性；它仍是受限样本，不是所有agent/飞机的成功率。只有功能和误差均通过后，才比较耗时和调用成本。

## 6 证据包和发布判定

统一存放 `tests/artifacts/precision-0.5.0/`，至少包含：

- `environment.json`、安装哈希/已加载buildId、版本和冻结的验收标准。
- `calls.jsonl` 及每次完整输入/返回、operation最终状态、错误和耗时。
- baseline、requested、effective、after、recovered状态及独立差异。
- UI对照图、原生图、几何图、见证点/截线、相机前后差异；标明哪些图片实际打开过。
- `checks.json`：testId、expected、actual、tolerance、evidence路径、pass/fail/blocked/not_assessed；缺证据不得填pass。
- 性能全样本、工作包/属性/测试映射、失败台账及修订后复验结果。

**发布门槛：** 必需字段覆盖、T01–T20相关必需用例、E1–E3全部固定起点、恢复及既有核心功能回归通过；无未解决的错误对象修改、丢数据、场景残留、可写契约误报或恢复失真。性能门槛未达到时，不能宣称“高效迭代已验收”；必需功能blocked即未完成，不能按比例折算通过。

完成报告要分别写清四层状态：代码/离线检查完成、安装包已部署、DLL已加载、实机和效果验收通过。主观高还原度评价尚未取得时单列，不阻止报告客观测试结果，也不宣布用户已经认可外观。

本方案证明的是明确范围、容差和样本内的局部精修能力。后续若要声称“AI能独立建出C17级整机”，还必须追加从空白飞机开始的整机工程、真实参照误差评估、剩余复杂族以及更广泛的agent样本；不能由这次局部测试外推。
